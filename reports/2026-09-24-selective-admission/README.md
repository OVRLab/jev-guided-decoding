# R26-A: selective execution and full-suite cost profile

**Completed and independently audited; output-format admission failed. No fresh
benchmark score or larger-model superiority result.** This bounded pilot uses
50 already-exposed development cases. All owned cloud resources are deleted.

Estimated pilot cost **$3.5464**, cumulative **$46.17/$110**,
leaving approximately **$63.83** before tax/separate network.
The pilot stayed within its $6 reserve, included in the parent's $60 reserve.
[Cost and cleanup](cost-and-cleanup.json) conservatively charge the entire resource
creation-to-cleanup interval, including deletion time after compute stopped.
These are unit-rate estimates, not an invoice.

## What actually ran

[Protocol](../../research/selective-benchmark-admission-plan.md): ten R25 development
math and science cases each, 14 R23 MMLU-Pro validation cases, six R23 MuSR cases
and ten R23 IFBench prompts. Fixed seed 2601; native chat templates; length-sorted
batches of four; separate eight-case serial timing probes and eight-token warmups.
All profiles retain their frozen output ceilings and sampling parameters.

Original Granite uses the R25 seed-2501 live epoch-2 and constant epoch-1 adapters,
without new training. One Jev judgment follows each original draft. All six arms
retain native when p(correct) >= .5 or unavailable; otherwise Granite repairs with
a fresh exact-prefix cache. The branch remains after zero-indexed block 19.
Controls are blind, matched constant, same-live-weights constant strength, inverted
and within-task shuffled strength. Their routing also uses Jev; they are not fully
Jev-free deployments. All final tokens are generated by the named model.

**20/50 cases triggered repair and 30/50 actually skipped it in each arm.** Across
six arms that is 120 executed repairs and 180
retained-native decisions. All 50 Jev requests succeeded without retry or missing
feedback: 34,885 input tokens, $0.00146517.
This measures skipped repair execution, not saved Jev calls: every native draft was
queried. No always-repair latency counterfactual was executed in this pilot.

## What this says about the budget

These **rough GPU-work projections** weight observed per-case batch allocations
by the complete source's subject/family counts. MMLU-Pro uses one exposed case per
subject, MuSR two per family and IFBench ten prompts; they are not uncertainty
bounds or guaranteed quotes. Full MMLU-Pro's five-shot prompts differ from this
zero-shot pilot. Batches mix tasks, so an unusually long answer can inflate the
allocated time for neighboring questions from other tasks. Task-only scheduling
and representative samples need their own profile before a quote. A more efficient
serving engine can also change these costs.

| Profile | MMLU-Pro: 12,032 | MuSR: 756 | IFBench: 300 |
| --- | ---: | ---: | ---: |
| Granite 4.0-1B | $15.94 | $0.09 | $0.31 |
| Granite 4.2-3B (thinking) | $504.92 | $21.49 | $8.62 |
| Qwen3-4B-Instruct-2507 | $712.14 | $12.55 | $6.41 |
| Granite 4.0-1B + selective Jev repair | $16.33 | $0.15 | $0.42 |
| All three native models + all six repair controls | $1271.10 | $34.70 | $16.16 |

Deployment rows each include their own native generation; the last row instead
shares native drafts across the six experimental controls. Do not sum all table
rows. These estimates exclude model loading/warmup, serial diagnostic repeats,
Jev latency/API charges, independent graders, test containers, additional storage/network
and tax. The hourly unit rate includes this pilot's 80 GiB boot disk. Native
batching continues until its longest output ends, so padded work can be substantial; no unmeasured continuous-batching savings are claimed.
The [post-hoc outlier description](native-outliers.json) also records output
degeneration: Qwen's MMLU case 40 repeats `Final: I` until its 16,384-token ceiling,
with a four-row batch taking roughly 27 minutes. This is not all useful reasoning
work or an inherent price of the task. A prospectively declared stopping contract
and a more efficient runtime require validation before a revised quote.

A complete ten-task quote is **still not established**. The
[feasibility review](../../research/selective-benchmark-feasibility.md) records
remaining access, prompt/grader, code-isolation and repository-agent requirements.
GPQA still returned HTTP 403 with the owner token. BFCL's external search access is
not configured. SimpleQA needs an independently validated judge. SWE-bench needs a
fixed agent/container harness. Increasing a budget does not resolve these gaps.

The CPU-only [LongBench workload](long-context-workload.json) tokenizes all 503
records with all three pinned tokenizers and no generation. Most exceed the pilot
16K input limit; some exceed native model windows after output reserves. The
upstream full-record protocol permits declared first/last-half truncation, which
needs its own tested implementation and prefill profile. Short-question timings
cannot price those workloads. Full-source reruns containing development-exposed
cases must disclose that exposure and report untouched outcomes separately.
