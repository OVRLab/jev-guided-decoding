# R25 provider availability diagnostic

Registered 2026-09-23 after v3 received repeated HTTP 529 responses, while it is
still collecting training drafts. This is operational diagnosis, not a quality
endpoint or a change to the frozen worker/failure limit. No test outputs exist.

Make exactly one request from the local workstation using the same pinned Jev
model and private key, with the public state `One plus one equals two.` and a Noul
asking whether that statement is true. Use one attempt, a 30-second deadline,
and a separate durable $0.005 cap with the same $0.042/M-input rate and 65,536-token
maximum reservation. Include its charge in the combined $20 R25/$75 cumulative
accounting; it does not reset or extend the study's $0.25 ledger. Do not replay.

Save request, successful raw response or sanitized error diagnostics, timestamps
and budget reservation. Comparing a local result with worker responses can help
distinguish a server-path problem from wider provider availability; neither result
proves account-wide or platform-wide status. A successful trivial probe is not a
validated scientific score or proof that the next study request will succeed.
