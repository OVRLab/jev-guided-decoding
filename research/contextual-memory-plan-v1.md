# R31: matched contextual memory and feedback — prospective protocol v1

Registered 26 September 2026 after the completed and independently reconstructed
[R30 replication](../reports/2026-09-26-feedback-pairing/README.md), before any R31
native generation, Jev judgment, training or test inference. This final protocol
supersedes the [conditional draft](contextual-memory-study-draft.md). Engineering
tests used tiny random models and an exposed R29 training draft; they supply no
R31 quality result. Source and input hashes will be frozen at a clean commit.

## Motivation and question

R30 replicates a narrow native improvement: structured repair scores 32.16%
versus 28.65% original Granite, +3.52 pp with a 98.3333% adjusted interval
[+1.69,+5.73] pp. Both seeds preserve all 110 native passes. Local score placement
does not demonstrate an advantage over within-draft permutations. Repeated mean
scores 34.11% and the separately trained scalar branch 34.77%; the latter is a
secondary comparison. Same-checkpoint oracle flags score 32.16%. These findings
motivate, but do not prove, a correction-capacity or representation bottleneck.

Does a branch reading frozen, context-dependent Granite states improve repair
over an equally trained branch reading input embeddings at identical positions?
Does richer memory change the value of localized feedback? The finite comparison
crosses two memory types with three feedback forms and two training seeds.
No open-ended layer, learning-rate or candidate search is authorized by this protocol.

**Lead choice:** contextual scalar feedback, selected from earlier R30 evidence.
The earlier conditional draft proposed structured feedback as lead; this declared
change occurs before R31 inference. Both informative forms remain in the factorial
comparison. A new positive result is not a claim of architectural novelty or
ten-benchmark/larger-model superiority; see [prior art](contextual-memory-related-work.md).

## Models, information boundary and intervention

- Original dense `ibm-granite/granite-4.0-1b`, revision
  `6a7381ba1f54d684ff508d991aeb7dc580157103`, FP32, SDPA, frozen/evaluation mode.
  Its actual loaded parameter count is 1,631,750,144. Greedy generation uses at
  most 128 new tokens and 2,048 input tokens, without truncation or constrained
  grammar. Explicit native EOS behavior is preserved.
- Hosted `jev-1.13.0`, the unchanged R29 three-question payload judging each
  actual native draft field against the record, no references in its input.
  One single-attempt request per case. Structured uses the three probabilities;
  scalar repeats their arithmetic mean; constant uses 0.5 in every slot.
  Scalar still consumes three questions, with no asserted single-question equivalence.
- One unmodified prefill of the exact original prompt plus native draft token
  IDs, excluding terminal EOS, yields post-block-19 states. Pool each question's
  tokens and its available unique draft answer field into one detached vector.
  Missing/duplicate fields use question tokens only. Stable decoded-prefix
  alignment preserves original IDs and groups split Unicode bytes.
- The matched control pools the input embedding vectors at those **same** token
  positions. This differs from R29's standalone question/answer marker encoding.
  Neither memory sees target answers, oracle flags or future repair tokens.
  Save both FP32 3×2,048 tensors, exact IDs/positions, hashes and extraction work.
- Each condition trains the same 262,144-parameter rank-32 R29 residual branch
  after zero-indexed block 19 (the twentieth decoder block). The branch reads
  current hidden state and the three memory vectors, scales their contributions
  with `1-p`, and adds a bounded learned residual. The original model and Jev
  weights never train. Every final token is generated by Granite.
- Each repair starts from the exact native prompt/draft tokens and the unchanged
  repair instruction, with a fresh independent cache. The branch first acts at
  the repair boundary and then at every new repair-token decision. There is no
  intervention on every layer and no access to Jev hidden states.
- An all-one feedback vector disables the branch **on the repair prompt**; it
  does not return the saved native answer. This study does not add a retention
  policy or claim conditional-dispatch savings.

## Data, training and selection

Generate 512 train, 64 development and 256 held-out test worlds, each split evenly
between temporal and compositional tracking, using seed 31001. Reject exact prompt
overlap with all R29 and R30 worlds and independently replay every text reference
as a location graph. Retain vocabulary/templates to isolate the memory change;
this is an authored mechanism test, not unseen-template or public-task transfer.
Rooms and answer multiplicities remain naturally sampled. Report answer balance
and retrospective constant-room references; these are not model runs.

Native drafts and one Jev request are recorded for all train/development cases.
Train twelve adapters: embedding/contextual × structured/scalar/constant × seeds
3101/3102. All receive the same 512 examples for two epochs, identical initialization
within each seed, identical shuffled order using `seed+epoch`, AdamW learning rate
0.001, weight decay zero, accumulation eight, gradient-norm clipping at one and
rank 32. Only branch parameters receive gradients. Correct native drafts supply
their exact original tokens as preservation targets; incorrect drafts use the
independently constructed three room answers plus EOS as correction targets.

For every condition/seed, select the earliest epoch maximizing development
all-three-correct accuracy. Save both epochs, original initialization, targets,
loss/update order, actual feedback and memory digests. Freeze all selected weights
before any test draft generation; no test-tuned threshold, checkpoint or extra epoch.
Matched arms share the expanded training set, so R29-vs-R31 absolute differences
cannot isolate memory or training-size effects.

## Test arms and work accounting

On every test case record original native output and untrained blind repair.
Record all twelve trained conditions. For each of the eight informatively trained
adapters (two memory types × structured/scalar × two seeds), additionally record:

1. Same-checkpoint constant 0.5 feedback.
2. Same-checkpoint feedback from the next sorted case in the same test family,
   wrapping at the end; scalar takes that donor's repeated mean.
3. Same-checkpoint correctness-oracle flags, clearly nondeployable; scalar takes
   the repeated mean of the flags as well.

The diagnostic constants differ from separately constant-trained adapters. All
cases, including native passes and uniform score vectors, remain in every denominator.
This yields **38 test outputs per case**, or 9,728 test outputs, plus 576 train/dev
native drafts and 1,536 development repairs: **11,840 generated outputs** total.
There are **832 API requests**, **832 memory extractions**, **12,288 training examples
processed** and **1,536 optimizer updates**. Report actual tokens, processed tokens,
serialized timings, digest overhead, API usage and model/extraction work separately.
Equal generation ceilings do not establish equal computation; these are serial
research measurements, not optimized serving latency. Jev's resources count toward
system cost and scale even though its parameter count is undisclosed.

## Outcomes and interpretation

Primary outcome is all three requested room names correct under the unchanged
R29 grader. Reference truth never constrains generation. Four primary paired effects:

1. Contextual scalar minus original native Granite.
2. Contextual scalar minus position-matched embedding scalar.
3. Contextual structured minus contextual scalar.
4. Contextual scalar minus its same-checkpoint donor feedback.

Average fixed training seeds within each world; the 256 worlds, not 512 seed-world
outputs, are sampling units. Use 10,000 paired bootstrap draws within each family,
seed 3100, descriptive 95% intervals and Bonferroni-adjusted nominal 98.75% intervals
for these four contrasts. Intervals are conditional on two trained seeds; they do
not estimate uncertainty over arbitrary retraining.

Secondary comparisons cover each trained condition against native and blind,
informative branches against their constant/donor/oracle interventions, contextual
versus embedding for structured and constant training, and informative contextual
branches versus constant-trained contextual. Report the secondary interaction
`(contextual structured − contextual scalar) − (embedding structured − embedding scalar)`
per world. Secondary intervals are descriptive, not a second confirmatory family.
Report every per-seed score, family score, field accuracy, formatting, length stop,
native failure repaired/pass damaged and live-versus-donor token change.

A supported native improvement is reported as such even if another effect is
unresolved. A contextual-memory attribution needs its matched memory contrast;
runtime-information attribution needs its paired-feedback comparison. A positive
secondary candidate may justify a new prospective public validation, with its
selection disclosed. No single all-controls pass/fail label replaces these distinct
questions. Null intervals are not equivalence. Oracle transformations can be
off-distribution for the learned adapter and do not establish a capacity ceiling.
