# R12-A: local claim gate, execution version 1

Registered before live inference on 2026-09-21. The owner authorized full execution
of the [staged research plan](next-experiment.md). This is a critic experiment;
it is not final-answer accuracy for Granite, Jev, or their combination.

The population is newly authored, finite rule worlds with complete atomic claims.
An independent forward-closure oracle checks the entire canonical assertion.
Unrecognized paraphrases, compounds and explanations remain **unassessed**, never
silently false or certified correct. It certifies entailment, not a written proof.
This deliberately narrow grammar permits independent automatic grading without
pretending to have blinded human labels for arbitrary natural-language reasoning.

Sixty development worlds precede 100 separate gate worlds, with three sampled
Granite proposals each. There are six motifs: forward chains, conjunctions,
missing conditions, reversed implications, explicit negatives and distractors.
Development and gate use distinct evidence, entities and prose rendering templates;
elementary logical motifs overlap, so this is not proof of structural generalization.
Gate forward chains are longer. A separate authored contrast/arithmetic diagnostic
may be recorded but must not satisfy the generated-candidate admission gate.

The generator is the original pinned Granite checkpoint; temperature 1, top-p 1,
48 tokens per proposal, one batch per world, seed `72191 + index`. Its prompt
requests one intermediate assertion in a specified sentence grammar. No reference
truth values reach Granite or Jev. The target assertion is explicitly a question,
not a premise. Prompt staging and the grammar restrict generalization.

Jev `jev-1.13.0` receives original evidence and each complete candidate, with two
separate Nouls: local support and assessability. It receives neither the oracle nor
the prior tentative prefix. Restatements can be supported; there is no progress
gate. Token-identical candidates at one prefix are scored once; raw occurrences
remain recorded. Invalid frames retain their own outcome and are not sent as
complete assertions. Usage is reserved before a single attempt and settled only
for the exact requested model with valid usage. Any service failure stops the stage.

## Frozen admission criteria

All five must pass on the 100 gate worlds:

1. All planned worlds complete without provider/backend failures.
2. At least 80% of raw candidate occurrences have independently assessable full
   canonical claims. Format failure is retained in this coverage denominator.
3. At least 25 worlds offer a fully assessed, mixed correct/incorrect scored set.
4. On those mixed sets, the 95% paired world-bootstrap lower bound for Jev ranking
   accuracy minus mean-logprob ranking accuracy is above zero (5,000 draws,
   analysis seed 19371). Ties use model likelihood. Jev ranks support among its
   assessability-passing candidates (threshold 0.5); if none, use native likelihood.
5. Among worlds whose Jev-selected claim passes support 0.8 and assessability 0.5,
   the one-sided 95% Wilson upper bound on false **or uncertified** selections is
   at most 15%. One selection per independent world defines the unit. Unassessed
   selected text fails certification without being relabeled semantically false.

The 15% limit is a pilot admission tolerance, not a deployment reliability target.
Mixed-set ranking is a conditional metric: all-good, all-bad and unassessed sets
are separately counted. Publish coverage, opportunity, Brier score, calibration
bins, full judgments and independent labels. No quality claim follows from the
gate alone. A failed/inconclusive gate prevents a large confirmatory answer study.

The development data can identify failures before gate inference; any changed
prompt/rubric creates an explicit new development version and freeze. No changes
are permitted from inspecting gate outcomes. The data and code manifest are
generated by `research/experiments/claim_gate.py prepare` and committed before
execution. Stage time is 1,800 seconds, with cooperative 45-second proposal and
30-second API limits; no unbounded retry or resampling.
