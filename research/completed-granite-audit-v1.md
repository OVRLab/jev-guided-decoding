# R27 completed-Granite audit, version 1

Registered 25 September 2026 before inspecting fresh quality grades. Generation
has closed at its admitted deadline. Coverage is known: the original Granite,
self-refinement, six routed arms and Granite 4.2-3B cover every case; Qwen does not.
The user asks what these saved results establish. This is an offline analysis of
existing outputs, with no model generation, Jev call, cloud allocation or new cost.

## Fixed scope and unchanged evaluation

Grade exactly nine systems: original, guided, self_refine, blind, constant,
live_constant, inverted, shuffled and granite_4_2_3b. Require every system to cover
all 198 GPQA, 300 IFBench and 30 AIME cases. Separately report project-untouched
subsets of 196, 288 and 30. Do not drop malformed answers or length stops.
Qwen remains coverage/work-only: 4, 199 and 4 saved native outputs respectively;
its prompt-length-ordered partial subset is not a representative comparison.

Reuse the frozen v3 token, selection, Jev receipt, numeric and task scoring helpers,
including IFBench strict/loose evaluation, language seed 2701 and v3 choice/numeric
readout. Validate pinned evaluator/environment hashes before scoring. Preserve
original manifests, checkpoints, source hashes, raw files, completion refusal and
full-tranche auditor. Do not create a completion marker for the incomplete tranche.

Before any grade: verify source/data/reference/checkpoint bindings, backup hashes,
all recovery ancestors and source envelopes, completed job/batch consistency,
exact decoded tokens and hook placement, both completed Granite weight records,
full donor/decision/receipt coverage and exact selected-answer provenance. Permit
only the single final unfinished Qwen native job; retain its unmeasured work as
missing, never zero. Audit saved Qwen tokens but do not grade them.

## Reporting and interpretation

Report each task separately for all nine systems, including paired wins/losses,
the existing descriptive paired intervals, format and length-stop counts, and
recorded work/API usage. Do not form a ten-task mean or claim superiority from a
descriptive interval. Compare guided with original, self-refinement and every
feedback control; a native gain alone does not establish Jev-specific benefit.
Preserve negative results. Generation profiles differ for the larger Granite.
Interrupted partial work and reload time prevent an uninterrupted-latency claim.

Only aggregate counts/intervals, source hashes and work totals may be public;
questions, answers, reference text, token IDs and per-case grades stay private.
Report the unchanged conservative $103.83/$110 closure estimate separately from
recorded model work; it is not an invoice. This cannot complete the other seven
benchmarks or establish broad model superiority or architectural novelty.

## Implementation and validation

Add a separately named completed-system auditor and tests; reuse the frozen
helpers without modifying them. Tests first must reject missing Granite cases,
duplicate/unknown outputs, unfinished Granite jobs, missing completed-weight

Then run exact-token audits of both saved streams, inspect all failures before
